Do these once, in order

1

Create your GitHub account

This is your host. The free plan does everything you need.

  • Go to github.com/signup and sign up with any email.
  • Pick a username carefully — it becomes part of every tool's address: username.github.io/…. Short and clean is best (e.g. msjones).
  • Verify your email, and you're in. Skip any paid upgrade prompts.
2

Get the code for your tool

You need the contents of one index.html file. Two ways to get it.

  • Fast path: use the ready-made Student Picker below — copy it as-is and move on.
  • Your-own path: ask Gemini to build it. Paste this starter prompt, then copy the file it gives back:
✦ Ask Gemini
You are helping a teacher build a simple classroom web tool. Create ONE self-contained index.html file — all HTML, CSS, and JavaScript in that single file, with no external libraries or links. The tool should: [describe your tool in one or two sentences]. It must work on a laptop and iPad, with large, touch-friendly buttons and text big enough to read from across a room. Show me the complete file in one code block. Whenever I ask for a change later, always reply with the entire updated file, not just the part that changed.
The golden rule with Gemini: always ask for the complete file. You'll copy the whole thing into GitHub, so partial snippets won't help you.

3

Create a repository

A "repository" (or "repo") is just this project's folder, stored on GitHub.

  • Click the + at the top-right of GitHub → New repository.
  • Repository name: lowercase, no spaces — hyphens are fine. Try student-picker.
  • Set it to Public, tick Add a README file, then click Create repository.
The repo name becomes part of your web address, so name it like you'd name a link.
4

Add your index.html file

This puts your tool's code into the repo.

  • In your repo, click Add file → Create new file.
  • Name it exactly index.html (lowercase, with the dot).
  • Paste in the code you copied in Step 2.
  • Scroll down and click Commit changes (a "commit" just means "save this version").
Why that exact name? GitHub automatically shows a file called index.html as the home page of your site.
5

Turn on GitHub Pages

This is the switch that publishes your file to the web — for free.

  • In your repo, open Settings (top menu) → Pages (left sidebar).
  • Under Source, choose Deploy from a branch.
  • Set the branch to main and the folder to / (root), then click Save.
  • The first build is the slow one — it can take several minutes (occasionally up to ~10). Every change after that goes live in about a minute.
6

Visit your live tool

Your tool now has a real address you can open, bookmark, and share.

https://your-username.github.io/student-picker/
  • Open it on your own device first. Seeing a 404 right after Step 5? That's normal on a first deploy — give it a few minutes and refresh while it builds.
  • Drop the link into Google Classroom, a slide, or a QR code for students.
That's a real deployment. The same seven steps host any single-file tool you ever build — quiz timers, group makers, lab checklists, review games.
7

Make it your own (with Gemini)

The repeatable loop: change the file with Gemini, paste it back, commit, refresh.

  • Paste your current index.html into Gemini and describe one change.
  • Ask for the complete updated file, then copy it.
  • In GitHub, open index.html → click the pencil ✏️ → select all, paste the new version → Commit changes.
  • Refresh your live link. If a change doesn't show, do a hard refresh: Ctrl/⌘ + Shift + R.

Copy-ready change requests to paste into Gemini:

✦"Replace the names with my class list, one per line: [paste your students]."
✦"Change the colors to our school colors, brown and orange."
✦"Make the picked name much bigger so it reads from the back of the room."
✦"Add a short drum-roll sound when I press Pick."
✦"Pick two students at once instead of one."

If something looks wrong

Page shows "404" or "There isn't a GitHub Pages site here"

It's usually just too soon — the first build is the slow one and can take several minutes. Give it time and refresh. Then check: the file is named exactly index.html, and Settings → Pages shows a green "Your site is live at…".

Blank white page

The file was likely saved empty or with a different name. Open the repo, confirm index.html has your code in it, and re-commit if needed.

My change isn't showing up

Your browser is showing a cached copy. Hard-refresh with Ctrl/⌘ + Shift + R. GitHub can also take a minute to rebuild after a commit.

Worried you'll break it

You won't — permanently. Every commit is a saved version. If a tool stops working, paste a version you know worked back into index.html and commit again.
